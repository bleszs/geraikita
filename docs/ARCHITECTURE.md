## Identitas dan data

server/identity.mjs mendaftarkan usaha/kelompok dari formulir dan menerbitkan sesi. Kata sandi disimpan sebagai hash scrypt dengan salt acak. Cookie HttpOnly, SameSite Strict; mutasi memerlukan CSRF dan origin sesuai. Login dibatasi per IP/email. Keanggotaan berasal dari akun dan kode undangan, tanpa pergantian profil publik.

Pengaturan akun memakai sesi/CSRF yang sama. Endpoint account/profile mengubah nama usaha sendiri; account/password memverifikasi kata sandi lama lalu memperbarui hash dan menghapus sesi lain dalam transaksi atomik. Delapan kegagalan verifikasi per akun dibatasi selama sepuluh menit. community/settings dan community/invite hanya untuk pengelola. Rotasi kode memakai expectedCode agar retry tidak mengganti dua kali. Bootstrap memuat email/tanggal akun sendiri melalui identity.details, tanpa hash/salt atau email anggota lain.

server/store.mjs hanya membuat/memigrasikan schema. Tidak mengisi katalog, histori atau penawaran. Default database data/gerai-kita-live.sqlite; DATABASE_PATH dapat menggantinya. Registrasi membuat identitas dan saldo kosong; anggota yang bergabung mendapat identitas bahan bersama yang benar-benar telah diatur pengelola, dengan saldo nol.

Semua operasi domain menyertakan workspace_id dan business_id dari sesi. Konfigurasi pemasok hanya dapat diubah pemilik kelompok. Settings dan quote_json menyimpan bahan dan harga dari formulir; quote_expires menyimpan tenggat sebenarnya. Siklus baru menghapus penawaran aktif, mempertahankan identitas bahan dan ledger.

## Domain

operations.mjs mengelola katalog/resep dan barang masuk. service.mjs mengonfirmasi penjualan dengan snapshot harga/resep saat itu. collective.mjs membekukan pembagian yang disetujui dan mencatat batch fisik; surplus.mjs menangani tawaran/reservasi/transfer. ## Perangkat dan AI

Service worker hanya menyimpan aset shell, tidak API. IndexedDB gerai-kita-device-v2 menyimpan snapshot, draft dan proof tindakan per scope akun/kelompok. Proof harus tersimpan sebelum mutasi stok dikirim. Respons yang hilang dikonsiliasi melalui bootstrap sebelum pengiriman ulang; tidak ada auto-sync. Keluar akun membersihkan snapshot aktif.

Extractor mendapat katalog akun setiap request. Parser memeriksa bukti menu/jumlah; keluaran model harus sesuai schema dan bukti itu. Harga/resep dihitung oleh domain. Input ambigu ditahan untuk review manual. Forecast memakai pemakaian yang terkonfirmasi, mengecualikan hari berjalan dan tanggal mendatang, serta tidak membuat estimasi saat histori kurang dari tujuh hari lengkap.

Pencatatan suara memakai `public/voice.js` untuk MediaRecorder dan state memori, tanpa audio/transkrip draft di IndexedDB. `POST /api/transcriptions` memerlukan sesi/origin/CSRF, body terpisah maksimum sekitar 1,4 MB untuk 1 MiB audio base64; endpoint lain tetap 64 KiB. `server/transcriber.mjs` memverifikasi file model, mengecek kesiapan sekali per proses, membatasi satu inferensi dan menjalankan Python tersembunyi dengan stdin/stdout, deadline 90 detik dan pembatalan saat koneksi ditutup. `server/ml/transcribe.py` mendekode BytesIO secara terbatas ke PCM mono 16 kHz, maksimum 30 detik, lalu memakai Whisper Tiny multilingual CPU int8 dengan VAD dan penyaringan segmen. Tidak ada file rekaman atau penulisan SQLite. Browser menampilkan hasil untuk dikoreksi; **Gunakan teks** hanya menambahkan ke catatan, kemudian ekstraksi/review/konfirmasi tetap diperlukan. Navigasi/logout/offline/perubahan scope membatalkan audio dan hasil terlambat. Dependensi `.venv-voice` terpisah dari `.venv-ml`; model dipasang eksplisit dan inferensi tidak mengunduh. Panduan: FORECAST_READINESS.md.

Replikasi UCI terpisah dari runtime: fetch-uci-retail.py memverifikasi ZIP/XLSX terhadap source lock lokal sebelum parsing, uci_retail.py mengagregasi event invoice per negara/tanggal dan memilih negara hanya dari development. File turunan tidak memuat CustomerID/Description. benchmark-uci-retail.mjs memakai trainer Ridge yang sama tanpa perubahan, menyimpan semua model sebelum scoring eksternal; uci-evaluation.mjs menghitung target dua hari serta error normalized/raw. verify-uci-retail.mjs memeriksa agregasi ulang, hash dan refit deterministik; summarize-uci-retail.mjs hanya analisis deskriptif setelah scoring. Public provenance menandai content SHA1, bukan Git commit. Tidak ada akses SQLite atau aktivasi akun pada benchmark ini. Sumber/zero policy/normalisasi dicatat pada datasets/public/uci-online-retail/README.md.

Transfer sales-only v0.18 juga terpisah: sales_features.py membentuk fitur relatif tanpa stockout/log level absolut; benchmark-transfer.py melatih dan memilih model hanya dari FreshRetailNet, menyimpan model/parameter sebelum parsing workbook target, lalu menguji bobot tetap pada kelompok UCI yang belum dinilai. Source loading/estimator menggunakan helper benchmark sebelumnya tanpa mengubah artefak/implementasi v2. verify-transfer.py memeriksa source hash, agregat workbook, refit sumber, koreksi dan prediksi; summarize-transfer.py hanya menjelaskan kegagalan setelah test. Tujuh tes Python transfer ditambahkan, sehingga total Python 19 dan keseluruhan 123. Hasil tidak memengaruhi registry akun dan belum mengalahkan baseline. Panduan: BOOSTING_TRANSFER.md.

V0.20 menambah benchmark ASR terpisah dari SQLite: `fetch-fleurs.py` memverifikasi shard test Indonesia; `prepare-fleurs.py` membaca batch PyArrow melalui `.venv-speech-data`, `prepare-fleurs.mjs` memilih hash tanpa melihat hasil, dan `prepare-fleurs-audio.py` mengubah representasi PCM di `.venv-voice`. `benchmark-speech.mjs` membekukan hash sumber/model/manifest sebelum memanggil transcriber produksi berurutan. `speech-evaluation.mjs` menghitung WER/CER dengan kegagalan sebagai hipotesis kosong. `verify-speech.mjs` melakukan preparasi sumber ulang, seluruh perhitungan skor/durasi, serta delapan inferensi ulang yang sudah ditetapkan. Analisis setelah scoring tidak melakukan tuning. Tambahan delapan tes Node menjadikan total 107 Node + 16 browser + 26 Python = 149 unik. Tidak ada perubahan kode runtime pada rilis benchmark ini. [Panduan dan batas](FLEURS_ASR.md).

V0.21 memakai `asr-comparison-data.py` dan `selectFreshComparison` untuk mengecualikan seluruh kelompok/teks/audio yang sudah dinilai serta overlap validation-test, lalu memilih satu rekaman per kalimat. `comparison-transcribe.py` mengimpor fungsi transkripsi produksi yang tidak diubah dan memasok model Tiny/Base melalui pemuat lokal setelah validasi audio. Node tetap memakai validator payload dan pengelolaan subprocess produksi. `benchmark-asr-comparison.mjs` mengevaluasi validation, menulis keputusan immutable beserta hash sebelum test, lalu menilai kedua kandidat dengan urutan bergantian. Verifier memisahkan audit file/skor yang lulus dari repeat inferensi yang gagal; laporan menyimpan perubahan teks dan skor, tanpa mengganti hasil utama. Model aktif tetap Tiny, Base hanya kandidat riset. Tambahan delapan tes Node: 115 Node + 16 browser + 26 Python = 157 unik. [Panduan](ASR_COMPARISON.md).
